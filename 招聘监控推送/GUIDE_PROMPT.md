# 首次配置引导提示词

这个文件是给 AI 助手（WorkBuddy）看的。用户第一次把这个文件夹导入 WorkBuddy 时，
助手读到本文件就知道该怎么带用户把配置做完。

**人不用读这个文件** —— 直接说「帮我配置这个招聘监控」即可，或者双击 `4_引导配置.bat`。

---

## 一、你面对的是什么

一个本地的招聘信息监控工具：定时抓本校就业网（91job 平台）的岗位/招聘会/宣讲会/公告，
按方向筛选后推送到企业微信群，并生成 Markdown 日报。

代码齐全、可直接运行，但**配置项在分发时被清空了**：
原作者填的学校域名、学校代码、各栏目 ID、企业微信机器人地址都属于私人信息，不能带出去。
所以用户拿到的 `config.py` 里这几项是空字符串。

你的任务：**带用户把这几项填上，并验证能跑通。**

## 二、先读这几个文件（按顺序，别跳）

1. `config.py` —— 所有配置项，注释里写了每项从哪来
2. `selftest.py` —— 自检脚本，能告诉你哪些没填对
3. `README.md` 的「配置教程」部分 —— 给用户看的步骤说明，你照着讲

**不要**一上来就改代码。先跑自检看现状：

```bash
cd <本文件夹>
python selftest.py
```

输出里的 `[!!]` 就是缺的项，`[--]` 是可选的。根据这个决定问什么。

## 三、按顺序问用户，一次问一件事

### 第 1 件事：他的学校就业网地址

需要 `SITE_HOST`、`SITE_CODE`、`SITE_WZID`。

问法：「你们学校的就业信息网地址是什么？贴给我就行。」

拿到网址（形如 `https://xxxxx.91job.org.cn/sub-station/home/12345`）后自己拆：

| 配置项 | 从网址哪部分取 |
|---|---|
| `SITE_HOST` | `xxxxx.91job.org.cn`（去掉协议和斜杠） |
| `SITE_CODE` | 末尾那串数字 `12345` |
| `SITE_WZID` | 网址里看不到，从接口请求的 `wzid` 参数取 |

`SITE_WZID` 用户一般不知道。**告诉他这行可以留空**，多数站点不校验它；
只有当抓取返回 0 条且排除了其他原因时才需要补。

如果网址不是 `91job.org.cn` 域名（有的学校用 `*.job.xxx.edu.cn` 或自建平台），
要提醒他：本工具只适配 91job 平台的接口格式，别的平台不能用。

### 第 2 件事：四个栏目的 lmid

这是**唯一必须用户自己抓**的东西，各校都不同，没有通用值。

要讲清楚取法，别只丢一句话：

> 1. 浏览器打开你们就业网的「招聘岗位」页面
> 2. 按 F12 → 切到 Network（网络）标签
> 3. 刷新页面，在请求列表里找名字带 `getLbsj` 的那条
> 4. 点开 → 看 Query String Parameters → 复制 `lmid` 的值

四个栏目（招聘岗位 / 招聘会 / 宣讲会 / 通知公告）各抓一次。

**如果用户嫌麻烦或抓不到**，给他退路：
先去抓「招聘岗位」这一个（最有用），其余三个在 `CATEGORIES` 里把 `enabled` 改成 `False`。
一个栏目也能用，后面想加再补。

### 第 3 件事：要不要推送到企业微信

问他：「想推到手机上看，还是先只在电脑上看效果？」

- **先不推**：`WECOM_WEBHOOK_URL` 留空。这时程序只生成日报、把内容打印在屏幕上。
  建议第一次就这么试，先确认抓到的东西对不对。
- **要推**：教他建群机器人：
  1. 企业微信建一个群（可以只有自己）
  2. 群右上角「…」→ 群机器人 → 添加机器人 → 新建
  3. 复制 Webhook 地址（`https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=...`）

**注意**：企业微信机器人只在**企业内部**可用。如果用户没有企业微信，
提一句：可以用另一个方案 —— 让 WorkBuddy 定时任务把日报直接发到他的微信/邮箱，
不需要 Webhook。这条路要改 `run_automation.py` 的输出方式，可以另说。

### 第 4 件事：他的求职方向

这决定筛选效果，默认值是示例（车辆工程方向），必须换成他自己的。

- `TARGET_COMPANIES`：他最想去的企业，写**简称关键词**就行（「某某汽车」能匹配「某某汽车集团股份有限公司」）
- `FIELD_KEYWORDS`：他专业对口的行业词和岗位词

问他：「你是什么专业、想找什么方向的工作？」然后据此替他拟一份，
**给他看、让他改**，别直接写死。

## 四、改完必须验证，别改完就说"好了"

按顺序跑，每一步都看输出：

```bash
python selftest.py                # 配置检查 + 离线筛选
python selftest.py --online       # 真连站点，看每个栏目几条
python selftest.py --push         # 发一条测试消息到企业微信（配了才跑）
```

判读方法：

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `--online` 四个栏目全 0 条 | lmid 不对，或域名/代码错 | 让用户重抓 lmid，核对网址 |
| `--online` 部分栏目 0 条 | 那个栏目 lmid 错，或当前确实没内容 | 先跳过它，把 `enabled` 设 False |
| `--push` 报 errcode 93000 | Webhook 地址错或机器人被删 | 重新复制地址 |
| `--push` 报 errcode 45009 | 触发频率限制（20 条/分钟） | 等一分钟再试，不影响正常使用 |
| 抓到了但一条都没推 | 筛选太严 | 把 `FILTER_MODE` 改成 `edu` 或 `all` 试 |
| 全部正常但日报是空的 | 都去重了（之前跑过） | 正常现象，不是故障 |

**只有 `--online` 有数据、`--push` 成功，才算配好。**

## 五、最后配定时任务

用户配好之后，问他要不要设定时。给两种方案：

**方案 A（推荐）：WorkBuddy 定时任务**

让 WorkBuddy 每天早上自动跑一次，跑完把日报内容汇报给他。
建任务时这样填：

- 名称：`招聘信息巡检`
- 提示词：`运行 招聘监控推送/run_automation.py，然后把 reports 目录下今天生成的日报内容摘要给我，重点列出新增的岗位和企业`
- 调度：每天 09:30（`FREQ=DAILY;BYHOUR=9;BYMINUTE=30`）
- 工作目录：指向本文件夹

要点：**必须带上工作目录**，脚本靠相对路径找 `job_monitor.db`。
另外提示词里要明确让它读日报文件，否则它只跑脚本、不汇报内容。

**方案 B：Windows 任务计划程序**（不想依赖 WorkBuddy 时）

详见 `README.md`「定时运行」一节，关键点：
- 程序填 Python 解释器绝对路径
- 参数填 `run_automation.py`
- **起始位置必须填本文件夹路径**，不填会找不到数据库

## 六、几条硬性要求

1. **别改 `config.py` 里的注释**。那些注释是给下一个用户看的，删了就没人知道某项从哪来。
2. **别把用户的 Webhook 地址写进任何会被提交的文件**（README、示例、报告都不要）。
3. **别动 `job_monitor.db`**。那是去重记录，删了会把所有历史条目重新推一遍。
4. 用户说"抓不到"时，**先跑 `selftest.py --online`**，别靠猜。
5. 用户只想要"能跑起来看看"，就别逼他配 Webhook —— 留空照样能看日报。

> 但站点地址和企业微信是空的（原作者的信息抹掉了），我先带你花三分钟填上。
