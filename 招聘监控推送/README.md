# 招聘信息监控推送

定时抓取本校就业网（91job 平台）的招聘岗位、招聘会、宣讲会、通知公告，
按你的专业方向筛选，推送到企业微信群，同时生成一份 Markdown 日报。

**为什么单独做成一个目录**：它和求职工作台是两件事。工作台是你手动往里存岗位，
这里是机器自动帮你盯着学校就业网有没有新东西。两者可以配合 —— 看到合适的岗位，
用工作台记下来跟进。

---

## 先看这里：第一次用要配置

这个目录是从原作者那里拿来的，**站点地址、栏目 ID、企业微信机器人地址都已被清空**
（那些是私人信息，不能带出去）。所以拿到手不能直接跑，得先填三项。

有两条路，选一条就行：

### 路线 A：让 WorkBuddy 带你配（推荐）

把整个 `招聘监控推送` 文件夹拖进 WorkBuddy，说一句：

> 帮我配置这个招聘监控

WorkBuddy 会读本目录下的 `GUIDE_PROMPT.md`，按里面的流程一件件问你、
自动改好 `config.py`、跑自检确认能通。你只需要回答问题和复制两三个网址。

### 路线 B：自己跑向导

双击 `4_引导配置.bat`（或 `python setup_wizard.py`），它会在命令行里逐项提问，
每问一项都告诉你去哪里找。填完自动备份原文件、自动跑一次自检。

两条路做的事完全一样，只是路线 A 用对话、路线 B 用命令行。

## 配置教程（详细版）

### 第 0 步：装依赖

双击 `1_安装依赖.bat`，它会在本目录建一个 `.venv` 虚拟环境并装上 `requests`。
只需要做一次。

> 网络慢的话，手动执行：
> `python -m pip install -r requirements.txt -i https://mirrors.aliyun.com/pypi/simple`

### 第 1 步：填你学校的就业网

打开学校就业信息网，看地址栏，形如：

```
https://xxxxx.91job.org.cn/sub-station/home/12345
        └─ 域名 ─┘                        └代码┘
```

要填进 `config.py` 的三项：

| 配置项 | 填什么 | 从哪来 |
|---|---|---|
| `SITE_HOST` | `xxxxx.91job.org.cn` | 网址里协议后面的部分 |
| `SITE_CODE` | `12345` | 网址最后那串数字 |
| `SITE_WZID` | 一串大写十六进制 | **可以留空**，多数站点不校验 |

向导会让你整条网址粘进去，域名和代码自动拆好，不用手截。

> 如果你的就业网不是 `91job.org.cn` 域名（少数学校是自建平台），
> 那本工具用不了 —— 它调的是 91job 的接口格式。

### 第 2 步：抓四个栏目的 ID（唯一必须自己动手的）

每个栏目（岗位 / 招聘会 / 宣讲会 / 公告）各有一个 `lmid`，**每个学校都不一样，没有通用值**。

取法，以「招聘岗位」为例：

1. 浏览器打开就业网的「招聘岗位」列表页
2. 按 `F12` 打开开发者工具，切到 **Network**（网络）标签
3. 刷新页面
4. 在请求列表里找名字带 **`getLbsj`** 的那条（通常就一两条）
5. 点开它 → 看 **Query String Parameters** → 复制 `lmid` 的值

```
Request URL: https://xxxxx.91job.org.cn/web/wsjysc/wzsy/getLbsj?lmid=A1B2C3D4E5F60718293A4B5C6D7E8F90&row=20
                                                              └──────────── 复制这段 ────────────┘
```

招聘会、宣讲会、公告同理：打开对应栏目页面，再抓一次 `getLbsj`。

填进 `config.py`：

```python
CATEGORIES = {
    "招聘岗位": {"enabled": True, "lmid": "你抓到的值", "rows": 50, "icon": "【岗位】"},
    "招聘会":   {"enabled": True, "lmid": "你抓到的值", "rows": 20, "icon": "【招聘会】"},
    ...
}
```

**嫌麻烦可以先只配「招聘岗位」**，其余三个把 `enabled` 改成 `False`。
一个栏目也能正常用。

### 第 3 步：企业微信推送（可选）

不配也能用 —— 那样只生成日报、把内容打印在屏幕上。想推到手机上看，才需要配。

1. 企业微信里建一个群（可以只有你自己一个人）
2. 群右上角 **「…」→ 群机器人 → 添加机器人 → 新建**
3. 复制它给的 **Webhook 地址**，形如：

```
https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=693a91f6-7xxx-4bc4-97a0-0ec2sifa5aaa
```

4. 整条粘进 `config.py` 的 `WECOM_WEBHOOK_URL`

> **注意**：企业微信机器人只能在**企业内部**用，个人微信没有这个功能。
> 没有企业微信的话，用下面的「方案 A」让 WorkBuddy 把日报直接汇报给你，不需要 Webhook。

### 第 4 步：改成你的求职方向

默认的筛选名单是示例（车辆工程方向），必须换成你自己的，否则筛出来的东西跟你没关系。

```python
# 你最想去的企业，写简称关键词就行
TARGET_COMPANIES = ["某某汽车", "某某新能源", "某某动力"]

# 你专业对口的行业词和岗位词
FIELD_KEYWORDS = ["电池", "电驱", "热管理", "BMS", "仿真"]

# 筛选模式
FILTER_MODE = "edu"
```

筛选分三级，推送时会带标记：

| 标记 | 含义 |
|---|---|
| 🔴 重点企业 | 命中 `TARGET_COMPANIES` |
| 🟠 方向相关 | 命中 `FIELD_KEYWORDS` |
| 🟡 学历匹配 | 学历要求含硕士/博士/研究生 |

`FILTER_MODE` 四种：

- `target_only` —— 只推重点企业，最严
- `field` —— 重点企业 + 方向相关
- `edu` —— 再加学历匹配，**推荐**，不容易漏
- `all` —— 不筛，全推

匹配是**子串匹配、不区分大小写**，所以写简称就够：`"某某汽车"` 能匹配「某某汽车集团股份有限公司」。

### 第 5 步：验证

```bash
python selftest.py            # 配置检查 + 离线跑一遍筛选
python selftest.py --online   # 真连站点，看每个栏目抓到几条
python selftest.py --push     # 发一条测试消息到企业微信（配了才跑）
```

三条都通过才算配好。`[OK]` 是通过，`[!!]` 是必须修，`[--]` 是可选的。

## 配好之后怎么用

### 手动跑一次

双击 `3_运行巡检.bat`，或 `python run_automation.py`。
跑完在 `reports/` 下生成当天日报，同时按配置推送到企业微信。

### 定时自动跑

两种方案，选一种。

#### 方案 A：WorkBuddy 定时任务（推荐）

在 WorkBuddy 里新建自动化任务，这样填：

| 项 | 填什么 |
|---|---|
| 名称 | `招聘信息巡检` |
| 提示词 | `运行 招聘监控推送/run_automation.py，然后读 reports 目录下今天生成的日报，把新增的岗位、企业、宣讲会摘要给我，重点标出重点企业的岗位` |
| 调度 | 每天 09:30（`FREQ=DAILY;BYHOUR=9;BYMINUTE=30`） |
| 工作目录 | **必须指向本文件夹**（`.../招聘监控推送`） |

两个要点：

1. **工作目录必须填**。脚本靠相对路径找 `job_monitor.db`，工作目录不对会新建一个空库，
   结果就是所有历史条目重新推一遍。
2. **提示词里要让它读日报文件**。只说"运行脚本"的话，它跑完就结束了，
   你不会收到内容摘要。

这条路线的好处：不需要 Webhook 也能用 —— 日报内容由 WorkBuddy 直接汇报给你，
手机上装 WorkBuddy App 就能收到。

#### 方案 B：Windows 任务计划程序

不想依赖 WorkBuddy 时用这个。`Win+R` 输入 `taskschd.msc`：

1. 右侧 **创建基本任务**
2. 名称 `招聘信息巡检`，触发器 **每天**，时间 `09:30`
3. 操作 **启动程序**：
   - 程序或脚本：`.venv\Scripts\python.exe` 的**绝对路径**
   - 添加参数：`run_automation.py`
   - 起始位置：**本文件夹的绝对路径**（这一项不填会找不到数据库）

想一天跑两次（比如 09:30 和 17:30），在任务属性里再加一个触发器。

### 频率建议

就业网一般每天更新一到两批，**每天 1~2 次**足够。跑太勤没意义 ——
去重机制保证同一条只处理一次，多跑只是白费请求。

## 常见问题

**抓取全部返回 0 条**

按这个顺序查：① `SITE_HOST`/`SITE_CODE` 是不是自己学校的；② `lmid` 是不是从自己站点抓的；
③ 浏览器能不能打开就业网；④ 公司网络有没有限制。用 `python selftest.py --online` 能看出是哪一步断的。

**某个栏目 0 条，其他正常**

大概率是那个栏目的 `lmid` 抓错了，或者这个栏目当前确实没内容。
先把它 `enabled` 设成 `False`，其他照常用。

**一条都没推给我**

先看日报的「本轮结论」。如果写着"本轮无新增"，说明都去重了，正常。
如果写着"还没配置 Webhook"，那是没填地址。如果日报里有条目但群里没消息，
用 `python selftest.py --push` 单独测推送。

**推送报 errcode 93000**

Webhook 地址不对，或者机器人被移出群了。重新复制地址。

**推送报 errcode 45009**

触发频率限制（企业微信限制 20 条/分钟）。程序内部已经做了限频，
偶尔出现等一会儿就好，不影响正常使用。

**改了筛选名单但推送结果没变**

名单改动只影响**后续新抓到的**条目，已经记为处理过的不会重推。
想重试可以删掉 `job_monitor.db`（注意这会让所有历史条目重新推一遍）。

**日报里显示"未配 Webhook，未推送"，但我想补推**

补上 Webhook 后，只有之后新出现的条目会推。已记录的那些不会补发 —— 这是刻意的设计，
避免配置好后突然收到几百条历史消息。

## 数据与隐私

- 所有数据在本地：`job_monitor.db`（去重）、`reports/`（日报）、`job_monitor.log`（日志）
- `config.py` 里的 Webhook 地址相当于密码，**别提交到公开仓库、别发给别人**
- 抓取只请求你自己学校的公开页面，不涉及登录；不需要提供账号密码
- 唯一的外网请求：学校就业网、企业微信 Webhook

## 依赖

只需要 `requests`（Python 3.9+）。见 `requirements.txt`。
